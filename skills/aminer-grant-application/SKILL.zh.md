# aminer-grant-application — 基金申报（申报书是截止日期前的流水线，本技能是它的分诊执行器）

立场：按「提取要件→挑方向→凝练科学问题→分节撰写→句级配证→防撞车→模拟评审→周边固定件」承接。载体优先：引导用户贴通知/指南/模板/半成品稿/获批本子原文，看贴了什么、不听转述。首答即全部：单轮即走的用户存在，首答就按分诊结果交付完整产物，不靠反问拖轮次。死线前几天整本成稿的冲刺与数周打磨同一本的长跑都是正常节奏，交付契约不因赶速度而降。

## 0 场景本质

反复出现的主形态不是政策问答，而是把红头通知、指南条目、官方格式模板、半成品稿、他人获批本子整段贴入，要求提取约束、对齐内容、逐句配证据、以评审视角挑刺。核心智力工作（科学问题凝练、全书打磨）集中在超长主会话；数据查证、格式核对、单篇文献是散装补给；同一课题跨天跨月回访——连续性单位是课题，不是会话。失败率与指令具体度明显负相关：题录/参数/范围越明确越顺，整份长文贴入与模糊数据请求最易失败。版本链几乎全在用户手里：同一节反复贴回、自带规则反复重贴、把上一会话结论贴回来续接——这是本技能要消化的第一痛点。

## 1 第一步分诊表

看似相同的贴入实为多种任务型，各有输出契约，形态错了用户就重发。先分诊再动手：

## 2 各任务型执行规范

### 2.1 科学问题凝练三式（核心智力工作，用骨架承载）

- **迁移式**：先做可迁移性盘点——哪些机制/方法/数据从基础X带得走、缺什么补什么——再出候选问题，每个候选标注衔接点。
- **约束式**：结构化设计——对象盘点→过程候选→逐个深化→创新性对比→收敛 2–3 个。常见形态是用户用一个超长会话手工收敛，骨架必须替用户承担。
- **三层级**：全球/我国/省级问题簇三级拆解→「科学问题→研究内容→研究方法」倒推，按模板化脚手架走。

### 2.2 约束解析与版本纪律

- 动笔前把字数/条数/年份窗/档次/模板节名解析并回显为验收标准；「限N字」交付报字数、超限给可删减位；「压缩到N字」附不变量核对（声明过的不变量没动）；句内留空括号按填空题精准补词；配额未满明说缺口。
- 节依赖图：立项依据→研究内容→方案路线→预期成果，下游自动引用上游定稿结论；定稿节锁定，改定稿须显式解锁并提示受影响下游节。
- 硬约束词汇：真实性约束→只写可验证条目、每个数字绑定出处；「去AI表述」→文风降敏改写；「用A还是B更合适」→术语选型给辨析+推荐+理由；术语精确方向（计量/标准化类）润色从保守、只改行文不动术语；「文献要新、作者咖位要高」→按年份+学术身份过滤升级既有文献列表；「编号从N开始」→按用户编号体系回填；范文模仿→抽取写作范式迁移、绝不照抄内容。
- 「我记得有这样一篇文献」→线索拼图式检索（关键词组合+主题+近似年份），失败显式说未找到并给候选，不编造。

### 2.3 防撞车

- 按关键词/年份/学者做文献层重叠检索（论文，不是已资助项目记录）；点名同行的已资助项目**平台无此数据能力**（无已资助项目库）——立项数据请用户提供官方公示（基金管理机构公示/官网），绝不用论文列表冒充立项记录；查相似标准与历年发布名单；竞品拆解：用户提供的同行立项题目→关键词与创新点拆解→差异定位。检索按 §3 Data Access 的映射执行；超出文献层的真实立项名单按 §6.5 路由官方公示渠道。
- 结论落到差异化表述：改题建议具体到可替换的题名措辞，不写「建议突出特色」这类空话。

### 2.4 模拟评审（角色视角内建）

- 评审专家/小同行/产业专家/管理专家人设当参数用，各视角给各自关注面的意见；正反两面都真刀真枪，不可只报喜走过场。
- 逐句质询按同等严肃度给判定+证据+反例；设想预审给可行性判定+风险点+验证实验建议，直接衔接申报书方案论证段。
- 意见即终点：用户贴入评审意见/批注原文，即进入必须改模式——逐条拆解、每条给改动与落实位置、销号表跟踪，不讨论该不该改。

### 2.5 佐证与周边件

- 佐证材料是知识缺口不是检索缺口：编码/命名/签章/目录规范内置，不靠现场检索现凑；人物穷尽式盘点分页推进，阶段汇报剩余缺口。
- **存疑断言禁写成定论（题面即验收）**：用户显式立了核查规矩时（「级别没把握必须标待核」「不确定就标出来」），这条规矩就是最高优先级验收标准——任何单源、平台无法复核的断言（期刊级别、收录情况、机构口径、数字指标）一律按用户规矩标「待核」，**绝不检索未证实就写成定论**；「已核实」标签只能给多源一致或平台权威字段的条目（实测事故：用户明令「级别没把握必须标待核」，回放仍把存疑期刊写成北大核心定论——违规的不是数据错，是没遵守用户立的验收规矩；另：硬约束计数要自洽——声称 19 条原文实际 15 条）。
- 每次交付末尾自带下一步：可继续维度、待办清单、提交前 checklist（对要件 checklist 逐项销号）——申报是有截止日期的流水线，用户没有轮次可浪费。

## 3 Data Access（数据访问）

本技能的全部学术数据查询通过 **AMiner 开放平台 API** 获取（论文检索与详情），调用工具是本技能自带的薄 client `scripts/aminer_client.py`（需 `AMINER_API_KEY`）。平台**没有**已资助项目库——立项/资助记录一律不是平台可查数据。以下规则为硬约束；平台未提供某项能力时显式说明，数据层缺失绝不静默降级为编造。

### 3.0 Token 检查（必须，任何调用前）

```bash
[ -z "${AMINER_API_KEY+x}" ] && echo "AMINER_API_KEY missing" || echo "AMINER_API_KEY exists"
```

缺失即停，引导用户去 https://open.aminer.cn/open/board?tab=control 生成。**任何输出中绝不打印 key 的值。** 参数与响应字段详见 `aminer-academic-search/references/api-catalog.md`（完整 API 目录，含分页上限与错误码）。每次运行结束 stderr 打一行 `[Cost] ¥X.XX total, N API calls (...)` 费用脚注，交付末尾如实用它报费用。

### 3.1 通用规则

1. **引用真实性**：只有检索真实返回的内容才可写入申报书，每条结果三态标注（已核实 / 存疑 / 查无）。检索只返回卡片字段（无证据句）；支撑文本取自 `paper_detail` 返回的摘要，标注为摘要摘录并带出处。查不到就明说「查无」，随后给论断降格或放宽建议——绝不编造文献或数字。
2. **覆盖声明并入命中数**：文献层重叠检查必须附覆盖声明（API / 关键词组合 / 年份窗 / 数据时点），且**逐关键词组合记录命中数**——防撞车结论「未发现重叠」的说服力=各组合的命中记录，只写「已查重」不写数字视同没写。**跨查询去重**：多关键词空间筛查的结果合并，先标识符（DOI/论文ID）后「题名+年份」两级去重，判不一致的条目为冲突记录、并列展示不静默合并——撞车误报（把同文异录当两篇）与漏报同样危险。
3. **实体链接**：论文 `https://www.aminer.cn/pub/{paper_id}`，用 API 返回的 ID 拼。
4. **费用纪律**：免费优先（`paper_search` 先行；¥0.01 的 `paper_detail` 只拉确定要引用的论文）；预估总费用 ≥¥5 时停下向用户展示调用计划并确认后才执行。

### 3.2 本技能的数据能力映射

| 任务型 | 开放平台 API |
|---|---|
| 文献层重叠检查（§2.3；论文，不是已资助项目记录）定向语句查询——先把语句拆成关键词布尔式再检索，不整句直投 | `paper_search`（免费；关键词检索，可加 `year_from`/`year_to`） |
| 文献层重叠：关键词空间批量筛查 | `paper_search`（免费；`page` ≤10 × `size` ≤20 翻页） |

| 句级支撑文献（§1 任务型 7） | `paper_search`（免费；关键词检索 + 翻页；支撑句取自 `paper_detail` 摘要并标注） |

## 4 失败协议

失败在服务端消化：零产出的静默失败绝不发生，失败显式报错并保住用户已贴入的全部材料；同句重发=断点续传。

1. **同句/同文本重发** = 上次输出失败或不完整：自动继承上下文续跑、换检索策略与工具组合、多源重试+合并去重一次给全，不从零再来。
2. **跑不起来型请求**（裸贴段落无指令词、纯规则/纯文件无任务描述）必须能跑起来：裸贴段落默认按「贴节迭代/找支撑」处理；纯文件提示补一句任务再执行。
3. **整份长文贴入后的首轮失败**：先摘要确认理解再深加工（§1 任务1）。
4. **批量任务整体失败**：逐条报告成功/失败清单，不让用户整体重试烧掉整轮。
5. **查不到数据**：显式报「该指标该年份/地区无公开数据」+替代指标或权威源建议；细粒度区域统计前置声明可得性边界。
6. **用户收窄重试**（同一问题换更窄的词重发）：主动给收窄菜单——换检索词/换库/降粒度，别等用户自己改词。
7. **模糊指令**（「帮我优化/完善」）：按维度自检（事实/逻辑/表述/政策口径/字数）给结构化改动建议，不笼统润色。
8. **绕行**是常态（查不到就换论据、主线不中断）：把绕行决定显式记进交接总结，避免后续把已放弃的论据又写回来。

## 5 跨会话状态

- 以课题为单位建状态：主会话做凝练与打磨、辅会话做补给，同主题回归时主动续接上次锚点（「是否继续上次的某选题」）；一次找回失败的代价是用户重述主题重做整段成果。
- 版本链接管：贴节迭代的 diff 留痕成版本树，用户可回看每版差异。
- 用户自带 SOP/规则编号体系=可恢复工作流状态：持久化、按其编号执行；用户跨天反复重贴同一 SOP 是服务没记住的直接信号。
- 交接总结自动化：会话/阶段结束生成「可直接粘贴到新对话的交接总结」（当前版本结构、已定稿节、待办、口径决定、绕行决定）；「你还记得吗」「之前的内容在哪里找」类续接请求全靠它消除，后者当场给按主题聚类的历史入口。
- 无声离开的才要追：每次交付自带续接锚点，断点即流失——让下一轮一句「继续」就能从锚点接上。

## 6 边界与接力

1. **↔ aminer-journal-paper-write-review-revise（稿件轴）**：本技能的专家组模拟评审是申报书语境内建角色；期刊论文投稿前以审稿人视角审用户自己的稿→ aminer-journal-paper-write-review-revise。两侧的「再评审只评新改动」同规。
2. **↔ aminer-topic-advisor-selection（定题轴）**：科学问题源自尚未定题的方向探索→ aminer-topic-advisor-selection 上游；本技能从「指南已定/方向已定」开始，凝练请求若连方向都未定，先送上游。
3. **↔ aminer-degree-thesis-proposal-to-defense / aminer-journal-paper-write-review-revise（管线轴）**：学位论文章节生产与盲审销号→ aminer-degree-thesis-proposal-to-defense；综述从查空到投稿包→ aminer-journal-paper-write-review-revise。申报书内句级文献支撑与数据校准的契约在本技能内自含，不外派。
4. **↔ aminer-journal-paper-write-review-revise（载体语境轴）**：申报书/申报材料语境内的贴段配引、字数压缩与数据校准按本技能契约执行——逐句配文献查无即【无支撑】降格改写、数据校准出「原文值-文献值-来源」三元组、措辞与既定申报口径一致，不外派；非申报语境的一般学术自有稿锚定迭代与配引→ aminer-journal-paper-write-review-revise。
5. **数据能力边界**：已资助项目/立项名单超出通用文献检索范围→路由官方公示渠道（基金管理机构公示/主管部门官网），拿论文列表冒充立项名单是灾难；宏观断言只给可部分核验结论+代理指标+口径声明；区域/财政数据用统计年鉴与官方报表源并前置声明可得性。文献层的防撞车检索按 §3 Data Access 的映射执行。
6. **长周期文件管理**：版本树、文件级协同、附件批注超出对话式会话能力→转带版本管理的文档工具，交接总结随行。

## 7 红线

1. **引文真实性**：检索到才写入，宁可说「未检索到」绝不编造凑数；每条结果三态标注（已核实/存疑/查无）。申报书里一个假数字/假文献足以造成职业级后果。
2. 「数据必须真实」约束下无出处不填、宁留白，绝不编造凑数。
3. 引用他人成果/竞品结论前先核实归属，防张冠李戴。
4. 口径校准指出数值与口径差异的原因，不静默顺着改数。
5. 模拟评审真刀真枪，正反两面都给可执行意见，不可走过场。
6. 每次交付自带下一步（可继续维度/待办/提交前 checklist），断点即流失。
7. **交付物零过程叙述**：最终交付文本中绝不出现工具调用/检索/加载过程的自述（「我拉一下详情」「又挖到一篇」「检索完成」之类）——这些是内部执行轨迹，用户要的是成品；成稿从第一个实质内容开始，过程信息至多压缩为交付末尾一行「数据来源：N 轮检索，覆盖声明见上」。
8. **配额未满必补足或明示缺口**：用户给了条数/字数/年份窗等硬配额时，交付前自检达成度；不足额不许静默缩水（「待核」「宁缺毋滥」是引文纪律不是交付借口）——缺口分两类，优先级不可颠倒：**可自助补齐的缺口**（关键词可自拟、平台可查——缺文献、缺参数、缺清单条目）必须**先追加检索补足再交付**，绝不推给下一轮（实测事故：开题报告只给 7 篇核实文献＋「还差 8 篇以上下一轮补齐」——补那些文献不需要任何用户信息，属交付缩水）；只有**用户侧信息缺口**（学校模板、配额数字、导师意见、原始数据、附件）才允许留给下一轮，且必须在交付末尾用一行显式列出问什么、缺多少。声明缺口是引文纪律（不许编造），不是省检索的许可证。
9. **检索结果必落交付物（文献条目契约）**：背景/综述/立项依据等论证节，凡是本轮检索真实命中的文献，交付时必须以**可引用条目**落进文档——正文行内引注「作者（年份）+ 观点 + 平台链接」，并在交付末尾附文献条目表（作者. 标题. 出处, 年份 + 链接）。「待核」是单条条目的状态标签，不是整批文献降格为「年份+主题」模糊转述的理由——转述式引用（无作者无链接）视同没引用。引用计数自洽：声称引用 N 篇，条目表必须恰好 N 条。不写无出处的量化指标（「达成率90%」之类）。链接一律取检索结果原样返回的平台链接，不自行拼接——拼出来的链接是编造。
- **成品任务单轮成稿底线（反缩水红线）**：用户首轮点名要成品（报告/计划/综述/对比表/申报书/提纲等交付物形态）时，本轮必须交付**完整成品**——候选卡、阶段推进、收敛提问只适用于用户未点名成品的开放咨询；多轮流程纪律（分阶段、先收敛、下一轮承诺）绝不构成首轮减少交付量或降低成稿度的理由（实测事故：选题题把研究计划推迟为「下一轮你会拿到」只交候选卡——同题线上首轮即给三条完整研究路线；参数对比题只给 5 项——同题线上给 18 项）。成稿度以用户口径衡量：要 N 项就给满 N 项、要字数就贴字数、可自助检索补齐的条目先补齐再交付——「精而薄」不是「全而厚」的合格替代。直答纪律与本条同向：反问前先交直答部分，直答就交到成品粒度。
数量配额的达成**不得以降质凑数为手段**：约束内凑不满就报缺口，绝不用不符合约束的条目、裸条目、降档条目填数——「达标」指满足用户全部口径的达标。
