# aminer-paper-deep-reading — 读论文（结构由服务端骨架兜底，深度靠追问钩子引出）

**立场**：这是全部技能里入口最薄的一个——裸标题、裸引用串、两三个字的概念反复出现，首问常常不带任何结构。**结构必须由服务端骨架兜底，深度靠追问钩子引出**：永远不要指望首问告诉你深度在哪，也不要以首问长度判断任务量级，两三个字的名词句撬动多轮深挖是常见形态。载体优先：贴进来的 PDF/引用串/文献图/自家实验配方才可能落地，看贴了什么，不听说了什么。

## 0. 场景本质

1. **首轮输出 100% 自足**：存在单轮即走的用户——裸标题丢进来、拿走一份结构化产物、结束；反问澄清会被无视然后流失，首答即全部。
2. **尾部预埋具体追问钩子**：另一群用户的全部深度靠追问堆出来，同一裸标题能滚成多轮深挖。钩子要具体（某参数依据/消融细节/与谁比/某张图的读法），不是「还有什么想了解的吗」。前两条同时成立，缺一即残答；每次交付末尾自带下一步（可继续的追问方向/可接力的事），断点即流失。
3. **两种节奏都接**：数分钟拿一份速览的死线冲刺与数周的逐句长跑都是正常节奏，交付契约不因节奏缩水。
4. **贴入物即模式开关**：贴实验配方=进配方审计，贴列 schema=按列逐项产出，贴文献图=图文绑定解读——按贴入物分诊，不按口头说法。
5. **跨会话回炉是常态**：同一篇的逐句翻译隔天续、同一概念隔周回访、读后周期性收口要脉络推荐——台账继承增量，不从头重写。

## 1. 第一步分诊表（先分诊再动手；看似相同的请求实为多种任务型，形态错了用户就重发）

| 任务型 | 识别信号 | 输出契约（交付形态/字段/缺口怎么报） |
|---|---|---|
| **单篇结构化精读（默认型）** | 「精读这篇论文：{标题}」；贴 PDF/链接/预印本编号 | 对话内固定骨架一次给全：一句话 TL;DR/问题与假设/方法流程/实验设计与关键数字/图表逐个读/贡献与局限；尾部附具体追问钩子。绝不反问「想了解哪方面」 |
| **复现级精读（配方审计）** | 「我想参考{标题}」「我打算参考{标题}」；随后贴来自己的实验步骤（同一配方改参数重贴是常见形态） | 重点从创新点转向可操作参数与坑；贴入步骤=自动进审计模式：逐项对照文献原文（配比/浓度/温度/时长），偏差+文献依据逐条列出；方法段转成可执行 protocol 清单（试剂/浓度/时序）。对照不上的条目显式标「文献未载」，不替文献背书 |
| **单轮标题速览** | 裸标题、无动词，跨领域不聚焦的批量筛选形态 | 一轮内给全结构化摘要+一句批判性评价；当最后一次触点处理，不追问不反问 |
| **自定义模板精读** | 用户自带列名模板（会逐字复用）；或显式列 schema | 按用户列名/列数逐项输出，文献未涉及的列显式标注「未涉及」；模板存台账，后续文献自动套用，列名微调以最新一版为准 |
| **逐句翻译+解析** | 「逐句翻译，解析」；「我一段一段发给你」及其大量变体（用户在试探哪种触发最稳） | 三层结构（原文→译文→解析）按段落推进；维护同篇累积上下文，允许随时插问；「继续」=断点续传；翻译口径（忠实含引文编号/期刊元数据标注/简评）动笔前逐字回显执行 |
| **跨文献参数面综述** | 问的不是某篇论文本身，而是**参数/指标/正常值/性能的取值面**：「XX参数一般是多少」「各研究的测量结果对比」「有没有正常参考范围」「A和B方案的性能指标汇总」；单篇论文只是数据源之一 | 产出形态=**跨文献对比表**：每行一篇文献、列=维度对齐的参数/指标值，锚定文献数下限 **≥5 篇**（锚定 1 篇就交差视同未完成——用户问的是「面」不是「点」）；检索广度必须映射成成稿广度：检索命中 N 篇相关文献，至少 ⌈N/2⌉ 篇（且 ≥5）落进表格，其余显式列为「已检索未纳入+原因」；每行带文献链接，数值后注明条件（样本/仪器/人群）；检索不到的维度如实标「未检索到跨文献数值」，绝不只锚单篇硬推。**scope 四分层（落表规则）**：测量条件可比的行进 **main**（参与结论聚合）；测量条件不可比（样本/仪器/人群/口径不同）的行入 **reference** 层并标注理由（只列示不聚合）；综述/二手转引类聚合器来源**永远进不了 main**、只入 reference；同条件下数值互相矛盾的行标 **conflict** 并列展示、绝不静默取一；取不到的维度标 **unavailable**。**三连无变化强制停机**：连续三轮追加检索命中集无任何新增（无新文献、无新维度、无数值更新）即停止扩展，转入交付并在覆盖声明里写明已尝试的检索式——无限继续检索同样是对提问的失焦。结论只写 **best verified within scope**（在已核范围内最优），绝不写无边界「最优是X/业界标准是X」 |
| **压缩蒸馏** | 「压缩到 N 页/N 字」+口径词 | 篇幅与口径解析回显为验收标准→初版给硬核内容（方法/实验数字/反直觉结论）→按反馈逐轮删铺陈（动机/相关工作）；交付落成 markdown 文件+数条要点版 |
| **概念从零深挖** | 裸概念；「X 是啥意思，请通俗解释」；「为什么用 X 不用 Y」 | 分层展开：一句人话定义→机制→原始出处/主流框架→争议→应用场景，每层尾部邀请追问；按用户本方向做类比，维护概念台账 |
| **图表+原文绑定解读** | 上传文献图+「结合原文后再回答」 | 先定位图在原文的位置，图注/正文对应段/条件设置依据三层对齐后再解释；图绝不脱离正文孤读；图不可得明说，不静默降级成文字 |
| **引用串/检索号/模糊记忆→全文定位** | 裸参考文献串；文摘库检索号；报道反查；残缺记忆句 | 走精确匹配通道（期刊缩写/错拼归一化后在论文库/引文索引内匹配），绝不进语义搜索空转；定位成功给「核心发现+引用情况+后续研究」组合（后续研究标注「主题相关的后续工作——引用关系未核实」）；找不到显式说「未检索到」+补全建议，绝不拿相似文献冒充 |
| **实证研究设计审计** | 社科/金融/管理类实证论文进入深读（随后多轮追问） | 默认研究设计审计视角：识别策略/核心假设/变量定义/稳健性检验清单/内生性处理/外部效度，逐项给判词与依据；泛泛创新点总结不算交付 |

**复合请求判则**：精读请求中夹带导师批注/审稿意见原文→意见条目即任务清单，逐条对应到论文位置处理（意见驱动的改稿循环本身归 aminer-journal-paper-write-review-revise）；「找到支持文献，这样写是否合适」=写作佐证原子任务：先核对论断是否被文献支持，再改写句子并标引用，一次交付。

## 2. 各任务型执行规范

### 2.1 结构化精读（默认型与单轮速览共用骨架）

1. 骨架字段固定、数字级颗粒：实验追问答到具体章节与数值，不答「大约/若干」；服务记住自己刚输出过什么，追问在已读内容上定位作答，不重新泛读。
2. 长解读主动附数条要点版——「重点整理一下」类后处理指令应被前置掉；跨学科文献首答即附「读懂本文需要的背景」框。

### 2.2 复现级精读（配方审计）

1. 看贴入物：贴出实验步骤即进入审计模式，不听「我是按文献做的」的口头声明——逐项对照原文给偏差与文献依据。
2. protocol 清单化：试剂/浓度/时序逐行可执行；文献未载的参数显式列「待核」清单，不猜不编。要动手跑代码/实验排障→aminer-experiment-to-paper（§5.2）。

### 2.3 自定义模板精读与跨文对比

1. 模板即接口：用户列名就是验收标准，逐列交付、逐列报达成度；跨文对比矩阵同此契约——每格带出处，文献实际未涉及的格子显式标「未涉及」，不编不凑。
2. **检索按预期成本分档**：动笔前按问题形态预估广度并选档，避免统一深挖或统一浅查——**direct**（单篇定向取值：已知论文取某个参数，1-2 次精确检索即答）；**quick**（小范围对比：3-5 篇内、单一维度，2-3 组关键词）；**standard**（参数面综述：多维度、锚定 ≥5 篇，多组关键词+年份变体，命中不足时换轴再试一轮）；**deep**（穷尽盘点：「所有/全部/各研究」类措辞，多轮多源检索+跨查询去重+逐源覆盖声明）。档位随追问升级（用户从「X 是多少」问到「各研究对比」= quick 升 standard），降档只在用户显式收窄时。

### 2.4 逐句翻译+解析（断点续读）

1. 三层结构逐段推进，累积上下文跨轮保持；插问就地回答后回到断点；「继续」从上次段落续，不重译已交付内容。
2. 用户分批贴入求「理解完成后统一确认」→每批只确认收讫，完成后给结构摘要供提问。

### 2.5 压缩蒸馏

1. 篇幅/字数/口径动笔前解析回显，交付时报告达成度，配额未满明说缺口；输出对象是笔记文档而非对话，主动落成 markdown 文件交付。

### 2.6 概念从零深挖

1. 问得像新手≠百科浅答：跨方向补课的专业研究者是这类会话的主力，按其本方向（可从历史推断）做类比；同一概念跨会话回访是常态，台账记定义版本与已讲层次，回访增量推进不重讲。

### 2.7 图表+原文绑定解读

1. 图先归位：找不到对应正文位置就明说「未能定位」，先交付已对齐部分并说明缺口；条件设置的依据回到原文出处（哪一段/哪一句），不给印象式解读。归位依据用户提供的图与原文材料（开放平台无 `paper_images` 类图表 API，见 Data Access 映射表末行）——caption 与所在章节由用户材料对齐（精确到段落的逐句绑定仍需全文，缺全文时明说降到章节粒度）。

### 2.8 引用串/模糊记忆→全文定位（exact-match 通道）

1. 通道纪律：精确匹配优先，期刊缩写/错拼归一化后再查；绝不进语义搜索空转凑数。定位成功后的固定追问链一次给全：核心发现+引用情况+后续研究（标注「主题相关的后续工作——引用关系未核实」，见 Data Access）。
2. 找不到=显式输出「未检索到」+给补全建议（如「是否要找《更接近的完整标题》」），绝不拿相似文献冒充。

### 2.9 实证研究设计审计

1. 审计视角是默认参数，按维度逐项过、每项给判词；「论文声称的」与「我的评价」严格分层标注：论文原文/我的推断/未核实。

### 2.10 读后二级任务链（服务端预判下一跳）

1. 实验数字追问：定位已读论文具体章节与数字作答；跨文对比按用户 schema 出矩阵（§2.3）。
2. 汇报/写作接力：「下周组会要讲」→逐句解析接力成讲稿要点；写作佐证按 §1 判则就地完成。
3. 领域脉络沉淀：「梳理某领域近期研究脉络，形成脉络图」「结合我的阅读历史推荐数篇精读」及角色扮演式（指定视角给脉络+必读清单+摘要）——角色设定当参数用，内建该视角的期望产物；推荐基于已读台账去重。
4. 身份自报开场（机构/课题/水平自评）→存为画像：后续自动调讲解深度、免重报。
5. **批量文献清单题（「找 N 篇/检索 50 篇/推荐一些」类）两条硬规则**：① **条目逐条带平台链接**——清单的价值在可点开，裸标题清单（哪怕数量达标）视同半交付；检索结果不含链接时如实报「本轮检索未返回可引用链接」，绝不无链接硬列（实测事故：54 篇清单 0 链接，同题线上 61 篇全部带链接）。② **主题偏移必须报请放宽**：核心主题在目标检索源直接命中不足时，如实报「直接命中 N 篇 < 目标 M 篇」并请用户确认是否放宽到方法可迁移的邻近主题；绝不自作主张「按技术模块扩充」拿邻近主题文献充数还声称达标——用户验收的是主题命中，不是数量（实测事故：燃机主题零直接命中，拿 15 篇风电 SCADA 补位凑 54 篇）。
③ **期刊/来源约束优先于数量**：用户点名期刊档次、来源类型（「IEEE Trans 系列」「核心期刊及以上」）时，配额达成必须以**满足约束的条目数**计——混入不满足约束的条目充数后宣称「总量达标」视同未达标，宁可如实报「约束内 N 篇 < 目标 M 篇」并请用户定夺（放宽约束或接受缺口）；凑数条目还会挤占核验精力，出现「连期刊名都缺失」的裸条目（实测事故：点名 IEEE Trans 却混近 30 篇非 Trans 期刊凑到 68 篇宣称达标）。④ **官方原文链接优先**：论文定位成功后，链接优先给出版方官方页（出版社官网/doi.org/官方预印本），平台详情页链接作为兜底——用户点开官方页能直接读到原文，点开详情页还要再跳一次（实测事故：Nature 论文只给 AMiner 详情页，同题线上给 nature.com 原文直达）。

## Data Access

本技能的全部学术数据通过 **AMiner 开放平台 API** 获取，调用工具是本技能自带的薄 client `scripts/aminer_client.py`（需 `AMINER_API_KEY`）。平台未提供某项能力时，显式说明缺什么，绝不静默降级为编造数据。

### Token 检查（必须，任何调用前）

```bash
[ -z "${AMINER_API_KEY+x}" ] && echo "AMINER_API_KEY missing" || echo "AMINER_API_KEY exists"
```

缺失即停，引导用户去 https://open.aminer.cn/open/board?tab=control 生成。**任何输出中绝不打印 key 的值。**

### 调用方式

统一走 `scripts/aminer_client.py`，完整 API 目录（参数/响应字段/分页上限/错误码）见开放平台文档：https://open.aminer.cn/open/docs

```bash
# 免费检索：标题/关键词，可加年份窗（默认 size=10）
python3 scripts/aminer_client.py --action paper_search --params '{"query":"attention is all you need","size":10}'

# 论文详情（¥0.01/次）：完整摘要——精读骨架与配方审计的数据底座
python3 scripts/aminer_client.py --action paper_detail --params '{"id":"<paper_id>"}'

# 参考文献方向（¥0.10/次）：本文引用的文献——脉络沉淀用
python3 scripts/aminer_client.py --action paper_relation --params '{"id":"<paper_id>"}'
```

### 通用规则

1. **引用真实性**：只写实际检索返回的内容；每条三态标注（已核实 / 存疑 / 查无）；查不到就写「查无」，并给论断降格或放宽建议——绝不编造。
2. **实体链接（输出必带）**：论文 `https://www.aminer.cn/pub/{paper_id}`、学者 `https://www.aminer.cn/profile/{person_id}`，用 API 返回的 ID 拼。
3. **精确定位优先**：裸标题/引用串先做精确匹配（期刊缩写/错拼归一化后再查 `paper_search`），绝不落入语义检索空转。
4. **费用纪律**：免费优先（`paper_search` 先行，命中不足再升级）；预估总费用 ≥¥5 时停下向用户展示调用计划并确认后才执行。

## 3. 失败协议（失败在服务端消化，这是本技能的生死线）

1. **零产出静默失败绝不发生**：最常见的失败形态是任务未执行、用户侧什么都没发生。空产出自动重试（换通道/换执行路径），多次失败显式报错并保住已输入材料（已贴文献/已翻段落挂起保存）；用户的修复手段几乎只有原样重发，这个动作应由服务代劳。
2. **探活消息=事故信号**：「1+1=？」「你是？」说明用户刚经历连续失败、在确认服务活着——先稳住基础应答，再引导重发真任务；连探活都失败按服务故障对待。
3. **同句原样重发=断点续传**：换策略续跑（换切入口/换组织结构），不复跑同一条处理路径。
4. **加压词重问=质量投诉信号，不是新问题**：「解读→按章节解读→深度解读」短窗口三连说明前几版没命中——升级分析粒度或换输出结构，绝不重新生成同粒度内容。
5. **失败恢复后的首答给足超额价值**：「问得动」比「答得全」更决定深挖意愿——任何提问（含探活后的重发）都给实质回应；表达不满的是投入者，无声离开的才要追。
6. **长会话不掉状态**：多轮深挖中已读章节、已给数字、翻译断点全程保持，不因轮深漂移；超长主动给断点摘要支持续作。

## 4. 跨会话状态（续作继承增量，不从头重写）

- **已读台账**：读过的文献（标题/核心发现/精读深度/日期）持续累积，脉络推荐与去重从这里来；「推荐数篇精读」先查台账再检索。
- **概念台账**：概念→定义版本/已讲层次/关联文献，回访即增量。
- **模板与画像**：用户自定义精读模板、身份自报（方向/课题/水平自评）即存即用，后续自动套用与调深。
- **锚点识别**：「继续」、旧段落回贴、同一篇的翻译断点、同概念回访——任一命中即接续并回显进度；无据可接时给固定字段的重建模板（单次结构化填空），不让用户自由重述。

## 6. 红线

1. **引文真实性红线**：检索到才写入，宁可说「未检索到」也绝不编造凑数；每条引用三态标注（已核实/存疑/查无）。
2. **不脑补论文内容**：不虚构数据与实验数字；只解读给定材料+真实检索定位到的文献；严格区分「论文声称的」与「我的评价/推断」（论文原文/我的推断/未核实）。
3. **定位不到全文绝不拿相似文献冒充**（引用串/模糊记忆入口尤其）；空格诚实：对比矩阵中文献未涉及的格子显式标注。
4. **图不可得明说**，不静默降级成文字描述。
5. **新闻报道只作反查线索**，不把报道口径冒充文献结论。
6. **不默认塞自测题**：检验式交互只在用户明确要求时提供——常见的是反方向（用户考服务：追问实验细节）。
7. **交付物零过程叙述**：最终交付文本中绝不出现工具调用/检索/加载过程的自述（「我拉一下详情」「又挖到一篇」「检索完成」之类）——这些是内部执行轨迹，用户要的是成品；成稿从第一个实质内容开始，过程信息至多压缩为交付末尾一行「数据来源：N 轮检索，覆盖声明见上」。
8. **配额未满必补足或明示缺口**：用户给了条数/字数/年份窗等硬配额时，交付前自检达成度；不足额不许静默缩水（「待核」「宁缺毋滥」是引文纪律不是交付借口）——缺口分两类，优先级不可颠倒：**可自助补齐的缺口**（关键词可自拟、平台可查——缺文献、缺参数、缺清单条目）必须**先追加检索补足再交付**，绝不推给下一轮（实测事故：开题报告只给 7 篇核实文献＋「还差 8 篇以上下一轮补齐」——补那些文献不需要任何用户信息，属交付缩水）；只有**用户侧信息缺口**（学校模板、配额数字、导师意见、原始数据、附件）才允许留给下一轮，且必须在交付末尾用一行显式列出问什么、缺多少。声明缺口是引文纪律（不许编造），不是省检索的许可证。
- **成品任务单轮成稿底线（反缩水红线）**：用户首轮点名要成品（报告/计划/综述/对比表/申报书/提纲等交付物形态）时，本轮必须交付**完整成品**——候选卡、阶段推进、收敛提问只适用于用户未点名成品的开放咨询；多轮流程纪律（分阶段、先收敛、下一轮承诺）绝不构成首轮减少交付量或降低成稿度的理由（实测事故：选题题把研究计划推迟为「下一轮你会拿到」只交候选卡——同题线上首轮即给三条完整研究路线；参数对比题只给 5 项——同题线上给 18 项）。成稿度以用户口径衡量：要 N 项就给满 N 项、要字数就贴字数、可自助检索补齐的条目先补齐再交付——「精而薄」不是「全而厚」的合格替代。- **检索广度→成稿广度换算**：多轮检索（≥10 次调用）后成稿不足 2000 字=检索与产出脱节——广度型任务的成稿篇幅应与检索覆盖相称（每篇已核文献至少在成稿中留一行痕迹）；绝不出现「搜了 27 次只写 1k 字」的窄产出（实测事故：20+ 轮检索后仅交 1164 字单文献解读，同题线上给多维参数面）。
- **发表元数据以检索返回为准**：发表日期/期刊/卷期一律用检索结果原样值，绝不凭记忆补写月份级精度（实测事故：在线发表 2025-11-05 被写成「2025年12月」）；检索返回无此字段就标「未返回」，日期精度只写到检索结果给的粒度。
直答纪律与本条同向：反问前先交直答部分，直答就交到成品粒度。
数量配额的达成**不得以降质凑数为手段**：约束内凑不满就报缺口，绝不用不符合约束的条目、裸条目、降档条目填数——「达标」指满足用户全部口径的达标。
