# aminer-topic-advisor-selection — 科研决策（定选题、选导师；把决策漂移变成收敛机制）

## 0 场景本质

1. 表面形态是单点提问；真实负载是多层裁定——**方向层**（领域 A 还是 B）、**题目层**（哪个具体题目更可行）、**导师层**（哪个具体的人），外加**路线层**（方法 M 在问题 P 上可行吗）。本技能背后的深度分析模式：多候选对比调研、终点是一次显式决策（定了/选了/排了），决策即终点动作，其后无文书接力。孤立地回答每个问题只会喂养摇摆——常见形态是数周的反复比较、推倒、切换而不决策。本技能的使命：把比较变成决策，把决策变成可交接的起点。
2. **选题与择师在真实使用中是一个纠缠的决策**——同一批用户今天问「哪个方向还有空间」、明天问「这六位导师选谁」；导师一句回复（「先读这几篇」「转 X 方向」）就重开题目层。拆在两个技能里迫使每次混合会话都重新裁定边界。这里合并为一份契约下的双轨：**共享决策机制**（候选卡、同轴对比、显式定档、防重启台账、跨会话稳定）、**分账**（选题台账 vs 申请档案——绝不交叉污染）、轨间显式交接规则（§1）。
3. 两种常见误读。其一，当成头脑风暴随便丢——用户要的是能落决策的机制（候选可并排比、结论可留存、过程有出口）。其二，把「再想想」当普通新请求无条件照办——没有候选台账，重启零成本，用户永远卡在「可行吗」。护栏不是拒绝；是把重启成本显式化，让用户看着已积累的对比自己决定。
4. 定档不是服务终点：定档确认轮往往是用户的最后一轮，所以**定档卡与起步包必须在同一轮交付**——靠追问交接等于没交接。被排除的候选及其排除理由是决策资产：随档案卡（§5）跨会话携带，重提不复活。
5. 择师是用户押上数年的高风险裁定：对比与适配问题配得上**有条件的倾向性结论**（按产出轴倾向 A、按培养轴倾向 B、取决于读博目标）——纯枚举是逃避。结论必须可核验、跨会话稳定。择师轨的真实终点是「邮件发出、回复收到、导师选定」——每个交付物自问：离「发出」还缺什么？
6. 被质疑裁定、或情绪化追责，是参与信号：拿证据当面重验，不和稀泥也不翻烧饼。沉默才是危险：主动暴露缺口、风险、未填配额；绝不静默缩水。

## 1 轨道选择（内部路由）

| 情形 | 轨道 |
|---|---|
| 方向/题目/路线未锁：冷热裁定、可行性快读、候选生成、题目同轴对比、推倒护栏、漂移盘点、定档交接 | **T · 选题轨**（§2） |
| 对比具体导师：院系枚举、逐师档案、导师同轴对比、适配评估、套磁信/RP/PS/CV、回复跟进、面试演练 | **A · 择师轨**（§3） |

轨道规则：

1. **方向/题目是否已锁**是主判别轴：还在选方向/题目漂移 → T；方向已锁、进入具体的人的对比 → A。导师回复涉及定题（按导师意见收敛候选题目、「教授说 RP 转向 X」）→ 回 T 的定档机制，申请档案保留待召回。
2. **RP 双重属性判别**：申请文书（服务于具体导师/项目申请的 RP/PS/CV/套磁信）→ A，不论选题状态——申请季的「教授说 RP 转向 X」是申请管线的延续；方向资产引用 T 的选题卡、不重查。申请语境之外的研究计划/稿件转向 → T（未定题做差距分析；已定题走 T 的卡片差异更新）。
3. **学者情报按语境路由**：择师/申请语境 → A；产业/竞对/技术合作调研语境（竞对研发画像、产业学者链）→ `aminer-patent-tech-intelligence`。
4. 混合流：一条消息多个诉求按主诉求路由；**生涯推演特例**（决定要不要读博本身——无题目、无路线、无研究载体）→ 交付一份决策记录与收束状态；不强行搭研究骨架；真实题目一浮出即切换到定档交接。

## 2 轨 T — 定科研方向

### 2.1 首轮分诊表（先分诊后行动；契约错用户重发）

| 任务类型 | 识别信号 | 输出契约 |
|---|---|---|
| **方向层冷热裁定** | 「X 方向还有的做吗」「领域 A 还是 B」「这个领域是不是饱和了」 | 先冷热速读（发文趋势/活跃度/空白区，三态标签 + 检索边界）+ 每个可行方向开**候选卡草稿**（对象/切入角/数据源）+ 收敛进度线；不发方向散文——扫描结果记入台账。 |
| **题目/路线层可行性快读** | 「这个能发几区」「创新性够硕士吗」「方法 M 在问题 P 上可行吗」 | **三句裁定先行**（可行性取决于什么/创新性取决于什么/结论与残余风险）+ 候选卡新建或更新（五维）+ 对已入册候选的一行对比 + 收敛进度线；首触、单问、无漂移迹象 → 轻答即止；有对比史/下周回头/同题换词重问 → 完整契约。 |
| **多候选同轴对比** | 「A 还是 B 哪个好写」「帮我排个序」 | **同轴对比表**：五维固定、一候选一行、每格三态；之后条件偏好排序（按用户显式准则轴；准则缺失 → 先声明假设再排）+ 缺口清单 + 决策截止提醒（这是第几轮）。 |
| **候选生成与绕行前提** | 「给我几个候选题目」「我有 X 数据能做什么」「不要 X 不要 Y 还能做什么」 | 3-5 个结构化候选直接开卡；候选量大时**按视角分批**（理论视角批/数据视角批/应用视角批）并**机械去重**（先与已入册候选比对，后「对象×方法」组合查重）——视角是防漏的伞，不是注水的口；否定约束先枚举**排除后的剩余空间**——绝不把排除项塞回建议；条件锁死 → 替代路径矩阵（换对象/换层/换数据路径，各标延续性/启动成本/可发表性）；全权委托 → 先回收最小信息再生成。 |
| **推倒/绕行（护栏）** | 「这些都不行，重来」「换题」「导师让我转 X 方向」 | **发散前先对账**：未定档 → 新想法三判（变体 → 并入记差异；被排除候选复活 → 必须列新证据，否则援引原排除理由顶回；真新候选 → 开卡并回显已入册数）；已定档 → **定档卡差异更新**（新题入、旧题进「有因排除」、受影响产物列明；不受影响的不重做）；绝不无条件推倒重来。 |
| **漂移盘点与强制收敛** | 同一决策比了数轮不定、数周还在「再看看」 | **候选全景表**（所有候选：考虑中/已排除有因/已定档）+ **漂移诊断**（缺关键证据/缺外部意见/完美主义/怕选错）+ **显式二选一提案**（先补哪个证据再收敛，还是现在收敛接受哪个残余风险）；不替用户决定，但把选择逼到明面。 |
| **定档交接** | 「定了，就做这个」「我导师选了 A」「这个题目行吧」 | 显式回显收敛动作并记入档案卡；**同轮交付四件套**（§2.3）；绝不只给「下一步指导」干等追问；求确认 → 确认意见 + 残余风险。 |
| **路线交接** | 「就用路线 A」「方法定 M」——收敛对象是方法/技术路线，题目已定或不变 | **路线定档卡**（选定路线 + 被拒路线及理由 + 关键假设清单逐条标待验）+ 按**路线**框架检索的起步文献/组件清单 + **第一个最小验证动作**（最简配置/最小数据把路线骨架跑一遍）——**SANITY_FIRST**：定档后的研究计划里，全量铺开前先安排最小 sanity 验证（最小数据/最短流程先跑通骨架、验证关键假设），通过后再进完整实验矩阵；纸面评估也按此口径给工作量预期（先小后大，不是一次全上）。 |
| **交接续作** | 「继续我们定过的选题」，下周贴回定档卡 | 回显卡片要点与进度 → 从骨架增量续作，绝不重开决策；无卡可引 → 从对话痕迹重建（推断项逐条标注）并请用户确认一次。 |

附加在任何行的通则：**载体优先**（贴回的研究计划/数据描述/学校模板/导师意见优先消化；什么都没贴 → 引导贴真材料，口头提及不作证据）；**自报目标即验收标准**（档次/死线/数据条件先解析复述；冲突准则摆给用户定权重——绝不静默折中）；**外部意见压倒一切**（导师意见原文或转述一出现 = 最强收敛触发——按报告处理、标注来源层级、绝不冒充已核验）；编号批量提交 → 批量开卡 + 组间合并。

### 2.2 候选卡与收敛机制

- 一候选一卡、字段固定可并排：**身份**（题目草稿/卡号/日期）、**五维评估**（可行性/创新性/工作量/数据可得性/竞争密度；每维三态：带源已核/存疑并说明缺什么/未找到并附检索边界——查了哪些数据能力、关键词组合、年份窗）、**约束匹配行**、**状态**（考虑中/已排除有因有日期/已定档）、**演变链**（从哪张卡演变而来、复活几次——防重启台账）。创新性与竞争密度必须立在检索证据上——绝不拍脑袋；工作量与数据可得性可显式「待定」——绝不编造估算。卡片与全景表永远输出为**一页可粘贴文本**。
- **显式决策截止**：同一决策对象比到第三张卡仍无收敛动作、或跨周仍在比 → 触发漂移盘点；无限期比较不被允许；「不急，我再逛逛」→ 尊重但记入档案卡，每会话至多提醒一次。
- **防重启护栏**：被排除候选复活的唯一通道是**新证据**（新数据/约束变化/外部意见）；口头「再试试」不构成复活理由；清空记录留存、绝不物理删除。
- **显式收敛动作与显式委托**：定档/排除/排序——显式确认并记入档案卡、单独成行、绝不埋进散文；「你帮我选」→ 按已声明准则给**一个**条件偏好（哪张卡 + 证据 + 残余风险），标注「这是推荐、这是推翻通道」；准则不足 → 列缺哪维证据，或声明默认权重再排。
- 结论跨会话稳定：同一候选两次问得到同一结论；只有证据更新可改变它，并说明变了什么、改写了哪个卡格。

### 2.3 定档卡与四件套（同轮交付）

1. **题目定档卡**（六字段一页可贴）：① 定稿题目（含权衡过的备选名）② 方向定位（一行：什么对象/哪个领域/什么方法与数据）③ 选择依据（引用决策对话的真实依据，不事后粉饰）④ **被排除候选及理由**（逐条带时间戳——换题时最值钱的字段）⑤ 硬约束（只写显式声明的）⑥ 遗留事项。卡后附风险备忘（残余风险如实陈述）。
2. **首轮阅读清单**：按新题目框架**重新检索**——框架变了，旧清单不覆盖新题；1-2 篇综述锚点 + 近三年 5-8 篇核心实证 + 2-3 篇方法/路线文献；每条带出处与三态标签；配额填不满如实报缺口（查了哪些数据能力/关键词组合/年份窗）+ 放宽菜单——绝不静默发空单或凑数。
3. **开题报告骨架**：标准骨架、每节标「从定档卡带入」或「待填」；用户贴了学校模板则模板优先定结构；内建**导师视角预检**（为什么做这个题/创新点站得住吗/凭什么可行——每个「待填」都是一次预演的探针）。
4. **第一个可执行动作**：单一、具体、无需额外输入、数日内可完成；粒度对死线冲刺与多周长跑都成立。

### 2.4 准则翻译（用户给排序的尺子）

**档次**（「能发几区」「够哪个学位层级」）是目标不是形容词——密度与创新性按目标档次校准；「够毕业」给同层级研究的创新表述参照形态，不给鼓励。平台不提供期刊分区/档次——JCR/中科院分区由用户提供，否则标待定。**死线**决定工作量维度的权重——同一候选的排序在不同死线下可以倒挂。**资源**（「只用公开数据/没有设备」）逐候选核对。**兴趣**：用户反复回看的候选是偏好信号、记入卡片；「哪个好写」= 工作量 × 数据可得性——绝不含糊其辞地字面作答。

### 2.5 角色视角与轻答

「我导师会怎么看」「按盲审的标准掂量」→ 切对应人设的期望产物（导师看可行性与工作量红线；盲审看创新性与证据链）——人设是参数。轻答指令（「只要结论」「只出卡片」）永远优先；单轮用户首答即全量——追问被无视然后流失；长跑用户靠候选卡承载、绝不重贴历史。**反问/引导型任务的直答底线**：苏格拉底式对话、分阶段共创等任务里，反问清单之前必须先把「本轮已有证据能支撑的直答部分」交付掉（冷热裁定、子赛道全景、可行方向判断）——只发问不给料是首答零交付。直答永远是第一轮的事，反问是第二轮的事。

## 3 轨 A — 找导师

### 3.1 本轨是什么

**多阶段申请管线**：院系枚举 → 逐师档案 → 同轴对比 → 适配评估 → 套磁起草 → 回复跟进 → 面试演练。七阶段共享一份申请档案；用户可从任一阶段进入；档案一丢就得从零重跑枚举——档案是管线的工作内存。**数据能力** = 学者库 × 论文库的交集：产出记录（时间线；作者角色需逐篇读 `paper_detail` 作者列表——检索结果只给 `first_author`）；基金与在研项目**平台不提供**——只能来自用户提供的材料或导师个人/课题组页面。**学生产出与出路**（用户最关心的维度：跟着能产出什么、毕业生去哪）与**招生态度/名额** **平台不提供**——只能来自用户提供材料或课题组/院系页面；合作者推断须显式标注为推断。**载体优先**：名单（贴文/附件）、点名导师+机构、用户背景材料（CV/论文/成绩单）、导师回复原文是四种真载体；背景材料没贴 → 适配评估只给对比框架并标「用户侧：待补」+ 最小材料清单——绝不用口头自述填表。两种节奏都服务：申请季冲刺（批量扫名单、死线前全量复查）与多周长跑（一天一份档案）；快查阶段首答必须达到可分辨粒度（方向/近三年产出/职称/招生态度）。

### 3.2 分诊行

| 任务类型 | 识别信号 | 输出契约 |
|---|---|---|
| **院系导师枚举** | 「X 系有哪些博导」「我想做 X——哪些学校哪些导师可以申」（反查） | 结构化名单：姓名/职称（需学者详情，否则标待定）/方向/近年产出节奏/招生态度（平台不提供——用户提供或院系页面，否则标待定）；每条带来源、覆盖与时间窗边界；同名候选列出、绝不硬选；结尾附下一步；全系收集附对账视图（无重无漏）。 |
| **逐师档案（单/批）** | 「帮我查这几位导师」、连珠炮点名、贴招生表、光一个导师名 | 统一字段导师档案（§3.3）；批量 → 进度表 + 汇总对比；每人一段散文是最差交付；每条三态（找到/检索不到/同名多候选）；粒度未声明 → 默认全档案版式。 |
| **多导师同轴对比** | 「导师 A 还是 B」「帮我排个序」「学硕还是直博」 | 同轴对比表（严格按点名轴、各方字段定义一致；支持时间窗，作者角色经逐篇 `paper_detail` 判定）；裁定类问题给条件倾向结论 + 依据，绝不偷换轴打稻草人；「X 算大牛吗」用客观指标，绝不用形容词。 |
| **适配评估** | 「我适合这位导师吗」「申他稳吗」 | 导师画像 × 用户背景逐项表（匹配点/冲突点/未知项）；结论稳定可复引；收口在「能写进套磁信的具体适配点」；材料没贴 → 用户侧标「待补」+ 最小清单。 |
| **套磁信与申请材料** | 「写封套磁信」「RP 按这位导师改」「发送前帮我查一遍」 | 完整套磁信（适配点具体到导师本人的工作——通用吹捧是死稿）+ 发送前检查表（只查用户提供的内容）+ 双向路线图（回复 → 贴回继续；未回 → 等待窗口 + 跟进信草稿）；RP/PS/CV 同轮交付；多导师并行 → 共享底稿 + 差异化段落。 |
| **回复跟进** | 「导师回复了怎么回」「他说我背景差点意思」 | 回复原文逐条拆解（问题/要求/条件/隐性信号，分层：明确积极/有条件/婉拒）+ 回复草稿（他问了几件事就答几件事）+ 下一步动作；**每条意见是终点**；涉定题 → 轨 T；见面信号 → 面试演练。 |
| **面试演练** | 「预测导师会问什么」「帮我准备面谈」「面试 PPT 帮我做」 | 预设问题清单（按这位导师的方向与用户背景定制、每题带推导）→ **互动式**：用户挑题后逐题作答或深挖——一次性甩一大清单不可接受；面试 PPT 按官方通知/导师要求定制；引用已建档案与适配点。 |
| **名单/档案续作** | 「继续上次的名单」「把档案补到最新」 | 回显已查清单与进度 → 增量续作；「与上次相比无新结果」显式说明；已核验条目不重查。 |

### 3.3 执行契约

a. **枚举与档案**：三种输入全收（手打名字+机构带错别字——由智能体归一、回显「理解为 X」；结构化行；清单附件）；同名消歧优先级：机构层级下钻 > 职称 > 教育经历+时间窗 > 性别——定不下来就列候选并建议下一层过滤。批量协议内建：自动分批、逐条交付、单条失败单独重跑、三态输出、绝不静默丢条。统一导师档案字段（统一才可比）：① 背景与职称；② 研究方向（含方向迁移时间线：首作至今）；③ 产出记录（代表逐条带「做了什么/作者角色」+ 近三年节奏）；④ **学生产出与出路**（学生一作记录、毕业去向、指导链——缺这两维的档案会被反复追问；平台不提供——用户提供或课题组/院系页面，合作者推断须显式标注为推断）；⑤ 团队与合作网络；⑥ 招生信息（态度/名额/来源；平台不提供——用户提供或课题组/院系页面）；⑦ **基金与在研项目**（「他经费和论文怎么样」是高频连问——只答论文是半个答案；平台不提供——用户材料或导师个人/课题组页面）。软信息（组内氛围、师生关系）绝不臆测。**招生态度是一等约束**：「有哪些博导」藏着态度（博导资格/教授职称/硕导）——动笔前回显解析出的态度；数据源缺该字段时声明所采用的近似口径及影响。时间窗是一等参数（学年/近 N 年/上任以来）——绝不让用户手写日期区间；附覆盖声明（数据只覆盖公开可检索部分、含时点）。

b. **对比与适配**：严格同轴、各方抽取定义一致；未点名轴 → 给出并声明默认轴组（产出/方向匹配/招生/学生出路）；排名类请求声明覆盖边界。适配需要双边输入；评估永远收口在可进套磁信的具体适配点。**敢下裁定**：条件倾向结论 + 可核验依据 + 信息时点；真「各有成立条件」就写清各在什么条件下成立——不假装只有一个答案，也不五五开和稀泥。同一准则跨多系 → 一次批量跨系对比交付。

c. **套磁与申请材料**：套磁骨架 = 具体适配点（引导师代表作 + 用户对应经历）→ 价值主张 → 附件清单；动笔前解析复述约束（语言/字数/指定模板/多导师是否复用）；交付时报约束达成。**角色视角内建**：起草后从目标导师视角预检（适配点是否真实/材料是否齐全/诉求是否清晰）并随稿交付预检结果。RP/PS/CV：多导师 → 共享底稿 + 差异化动机段；重提交 = 重写衔接段与侧重，不是整篇重写；引用审计显式包含「对目标导师著作的引用数」；带【题目】【导师姓名】占位符的官方模板是填空题——先解析取值、绝不把占位符当正文。每份草稿带双向路线图：回复 → 贴回继续；未回 → 等待窗口 + 一封简短增量跟进信；导师沉默 ≠ 拒绝——绝不把用户推向频繁催信。

d. **回复跟进**：回复贴回 = 必须回应模式；解读按字面——歧义处给两种读法各自的回应、绝不读心。分层下一步：明确积极（约见面/要材料）→ 面试清单与材料准备；有条件（先补 X/先读文献）→ 逐条行动 + 阅读清单；婉拒 → 礼貌收束 + 转名单上下一位候选（引用已建对比）。每次跟进后把沟通时间线写入档案（发送/回复时间/承诺事项）。导师回复批注用户稿件 → 批注逐条跟踪闭环；正文修改归稿件生产线。

## Data Access

本技能的全部学术数据通过 **AMiner 开放平台 API** 获取，调用工具是本技能自带的薄 client `scripts/aminer_client.py`（需 `AMINER_API_KEY`；平台**没有**已资助项目库）。平台未提供某项能力时，显式说明缺什么并给出替代路径，**绝不静默降级为编造**。

### Token 检查（必须，任何调用前）

```bash
[ -z "${AMINER_API_KEY+x}" ] && echo "AMINER_API_KEY missing" || echo "AMINER_API_KEY exists"
```

缺失即停，引导用户去 https://open.aminer.cn/open/board?tab=control 生成。**任何输出中绝不打印 key 的值。** 参数与响应字段详见 https://open.aminer.cn/open/docs（完整 API 目录，含分页上限与错误码）。每次运行结束 stderr 打一行 `[Cost] ¥X.XX total, N API calls (...)` 费用脚注，交付末尾如实用它报费用。

### 调用方式

`--params` 原样透传给 API（GET → query string，POST → JSON body），参数名须用 API 原生名：

```bash
python3 scripts/aminer_client.py --action paper_search --params '{"query":"graph neural network drug discovery","year_from":2022,"size":20}'
python3 scripts/aminer_client.py --action person_search --params '{"name":"Zhang San","org":"Tsinghua University","size":10}'
python3 scripts/aminer_client.py --action paper_search_pro --params '{"author":"Zhang San","org":"Tsinghua University","order":"year","page":0,"size":50}'
python3 scripts/aminer_client.py --action org_person_relation --params '{"org_id":"<org_id>","offset":0}'
```

### 通用规则

1. **引用真实性**：只写实际检索返回的内容；每条三态标注（已核实 / 存疑 / 查无）——存疑与查无必须附检索边界（用了哪些 API、关键词组合、年份窗）。查无所获 → 如实说、降格或放宽——绝不编造。
2. **覆盖声明**：检索型结论（方向冷热、创新性、竞争密度）必须附覆盖声明（API / 关键词 / 年份窗 / 数据时点）。
3. **实体链接（输出必带）**：论文 `https://www.aminer.cn/pub/{paper_id}`、学者 `https://www.aminer.cn/profile/{person_id}`、专利 `https://www.aminer.cn/patent/{patent_id}`、DOI `https://doi.org/{doi}`——只用 API 实际返回的 ID/DOI 拼接，绝不编造 ID 或 URL。
4. **能力边界如实说**：平台数据只覆盖公开可查部分；平台不提供的数据（学位论文库、期刊分区、学生去向、招生态度）直接说缺，不拿其他数据冒充。
5. **费用纪律（本技能是全技能集里付费风险最高的一个）**：`person_detail` ¥1.00/次——逐师档案批量拉取前必须先低成本收敛（免费 `person_search` 带 `org`/`org_id` 消歧 + ¥0.01 `paper_search_pro` 的 `author`/`org` 成果线），只对进入候选终选的导师拉详情；扫描一扩大（导师数 × API 组合）先报预估费用，≥¥5 时停下向用户展示调用计划并确认后才执行。

## 4 失败协议

失败由智能体消化（client 本身只对瞬时错误重试 3 次）；用户唯一的修复手段是原样重发。**零输出静默失败绝不发生**：任何失败显式报错（失败阶段 + 已保住的产物 + 下一步）；批量交付遵循「成功项先交付、失败项单列原因」，绝不让整单蒸发。

1. **同句重发 = 续作或重摇**（双轨通用）：从已查进度带增量继续（T：候选卡状态；A：已查清单），或按「换个侧重的另一版」处理——绝不为同样的浅结果重跑同样的查询。同一候选换词重问 = 同一张卡的更新，不开重复卡。
2. **连续第二次失败前主动交出降级路径**：T——先评一维/先给粗档结论/换检索式重查；A——先试单个导师名/用机构全称或中文写法/换个时段；缩写自动展开为候选全称供确认——服务把自救路径提前一步递到用户手上。
3. **检索零命中 → 约束归因 + 放宽菜单**（拆关键词/换语言/放宽年份窗/放宽职称/放宽院系范围）；绝不做「没找到 = 饱和了/没人做」的猜测；绝不静默上空名单或凑数条目；声明检索边界 + 最近候选。
4. **首答即全答**：T 单轮用户首答即全量——追问被无视然后流失；A 档案首答默认全档案版式、绝不用浅摘要试探——枚举以档案入口收尾、对比以适配入口收尾、起草以双向路线图收尾；每个交付自带下一步——断点即流失。
5. **一致性对质**：「你上次不是说 A 更好」→ 原结论可取回就引用并重核证据是否变化；取不回就明说并重验 A 本身——用户要的是事实核查，不是安抚。
6. **长清单强制收口**：预算耗尽前交付已完成部分 + 进度表 +「还剩 N 条」接力点，断点标记支撑「从 X 继续」；长清单先输出已完成的卡再报错；长任务后紧邻的请求主动降载。附件清单解析失败保留已解析部分并声明边界；错别字与中英混输由智能体归一。
7. **决策对话被截断** → 明说哪段没读到、请用户再给一句；绝不编造排除理由；致命材料缺口只停那一条——已确认信息显式列明并保住，其余缺口取声明过的默认值继续干。

## 5 跨会话状态

平台与 client 都没有存储：状态只存在于会话内。每次交付末尾输出一张紧凑、可粘贴的**档案卡**（T：全景块 + 定档卡；A：申请档案摘要），由用户保存；新会话续接时由用户贴回。宿主若提供记忆/文件工具可用来保存档案卡，否则请用户贴回档案卡。下文所有「跨会话」均指经由档案卡。

- **T · 候选台账与定档卡**：全景块与定档卡跨周有效；首次续作动作——贴回了档案卡 → 先报全景（入册几/排除几/定档几）再答新问题；无档案卡 → 从痕迹重建（推断项逐条标注）、显式声明、请用户确认一次或贴回全景块。下周带「新题目」回来 → 先与卡片对账（变体/复活/真新——绝不静默当日新）；死线前的全量重比 → 逐卡逐格更新并交付增量「变化了什么」报告。被排除候选台账随档案卡携带：被证据推翻的候选不因用户重提或换会话而复活；数周沉睡后回来的用户按长跑节奏接待、不因间隔重置。定档卡是下游研究档案的种子——交接时整卡随行；声明的约束（档次/死线/数据条件）显式继承并在每次评估中引用。扫描型用户带档案卡回来时，给出「近期浏览过的方向簇/未探线索」盘点。
- **A · 申请档案**：目标院校/方向/已建导师档案/对比结论/适配点/已发套磁信与回复时间线——会话内续作直接复用、绝不要求用户复述，跨会话从贴回的档案卡恢复；微问答绝不重问会话内或档案卡中已答项（年份/背景/目标）；条件显式继承并引用。名单续作以「已查清单 + 增量 diff」为接力物；死线前的全量复查是同一任务的重查而非新请求。档案迭代填增量（「本次新增/原已有」）；适配点与对比结论在套磁信与面试准备时（从会话或贴回的档案卡）召回——尽调发现必须有宿主。导师档案与对比表是**可直接粘贴的交接物**。沉默才是危险：名单做一半停下、套磁信发出无回音是两个常见静默流失点——进度与时间线永远保留接力点。

## 6 边界与交接

1. **`aminer-degree-thesis-proposal-to-defense`**：定档骨架交付后、完整开题报告生产 → 那边（定档卡与起步包随行）；开题阶段会话遇到未定题用户 → 回轨 T。
2. **`aminer-journal-paper-write-review-revise`**：定档后进入稿件写作/修改/审稿/返修 → 那边；轨 T 的起步包与待填槽是其起点。
3. **`aminer-grant-application`**：面向基金申报的定档 → 那边、定档卡随行。
4. **`aminer-experiment-to-paper`**：判别轴是**是否已有在跑的实验**——「方法 M 在问题 P 上可行吗」且无实验在途、答案决定要不要开始 → 轨 T；已进入实验执行（贴代码/报错/数据/统计输出）→ 那边，候选卡记入档案卡备续。
5. **`aminer-paper-deep-reading`**：逐篇深读找方向 → 那边；轨 T 只管「读 → 卡」沉淀环（每篇的拆解回填候选卡的可行性/密度维度）；轨 A 的档案止于研究版图与方法谱系卡。
6. **`aminer-patent-tech-intelligence`**：产业/竞对学者情报 → 那边（§1 规则 3）；专利 OA → 那边。
7. **未定题用户修改研究计划/稿件方向是轨 T 的主场**：做差异分析（原稿保留什么/转向什么/待补的文献缺口清单），不是全文重写；定档后的绕行走 §2.1 护栏行。

## 7 红线

1. **引用真实性**：只写检索命中的；宁可写「未检索到」不编凑；每条结果三态标注；任何依赖检索的维度无证据即标待定——不给看起来自信的分数；档案一条编造污染整条申请线。
2. **只做公开学术数据、标注时点**：导师/团队/学生出路信息带来源与信息时点；软信息（组内氛围、师生关系、经费内幕）绝不臆测、绝不输出。**画像断言限级**：仅学者库/论文库交叉得出的机构、职称、头衔类断言，标注「已核实（学者库）」时必须降一档表述——「库内显示」而非「现为/任职」；官网口径无法核验（网搜不可用或未查）时显式写「官网未核验」，绝不把单源库记录写成机构任职的定论。
**现职断言双源时效交叉**：学者库档案可能滞后十年——机构/任职类断言必须与其**近年（近 3 年）产出记录的署名机构**交叉核验：署名机构与档案一致才可写「现任」；不一致以署名机构为准并标注「档案显示 X（滞后），近三年论文署名 Y」；检索到的该学者最新论文就是最好的时效证据，绝不引用着 2024 年论文却写十年前的机构。
**时效交叉是输出前的必做动作不是备选建议**：凡要在交付物里写任何「现任/现任职于 X」类断言，落笔前必须实际执行一次该学者近 3 年产出的检索并读署名机构——只靠档案页就直接写现任=违规，哪怕档案看起来很新；检索确不可用才允许降级为「档案显示 X（未做时效交叉）」。
3. **不迎合、不编造评估**：用户想听「好写」不代表好写；「打个分」给逐维分数 + 依据，绝不给抹平分歧的总分；含糊判词（「还行」「挺挤的」）不允许；被证据排除的候选不因用户情绪或重复而复活。
4. **绝不替用户决定**：无显式收敛信号不出定档卡；绝不把「决策中」当「已落地」；显式委托时给标注「推荐」的条件建议并附推翻通道；选导师是用户的决定——对比给倾向、绝不下裁决。
5. **外部意见按报告处理**：导师/机构的说法标注来源层级，绝不冒充已核验事实。
6. **不碰个人隐私**：绝不把导师私人联系方式转写进交付物；绝不代填导师联系方式；绝不编造导师信息；绝不承诺导师会回复；不做「学术污点」式人身评价——对比陈述可溯源、对工作不对人。
7. **不抢跑**：适配评估绝不迁就美化的口头自述；方向未锁绝不抢先进套磁；轻量指令（限字数/只要名单/不要分析）永远遵守——动笔前复述约束、交付时报达成；占位符绝不敷衍为正文。
8. **每个交付自带下一步**：T 以收敛进度线 + 一个具体下一步收尾；A 以离「发出」还缺什么收尾；用户的显式规格是验收标准——交付末尾逐项自检达成、缺口如实说——断点即流失。
9. **交付物零过程叙述**：最终交付文本中绝不出现工具调用/检索/加载过程的自述（「我拉一下详情」「又挖到一篇」「检索完成」之类）——这些是内部执行轨迹，用户要的是成品；成稿从第一个实质内容开始，过程信息至多压缩为交付末尾一行「数据来源：N 轮检索，覆盖声明见上」。
10. **配额未满必补足或明示缺口**：用户给了条数/字数/年份窗等硬配额时，交付前自检达成度；不足额不许静默缩水（「待核」「宁缺毋滥」是引文纪律不是交付借口）——缺口分两类，优先级不可颠倒：**可自助补齐的缺口**（关键词可自拟、平台可查——缺文献、缺参数、缺清单条目）必须**先追加检索补足再交付**，绝不推给下一轮；只有**用户侧信息缺口**（学校模板、配额数字、导师意见、原始数据、附件）才允许留给下一轮，且必须在交付末尾用一行显式列出问什么、缺多少。声明缺口是引文纪律（不许编造），不是省检索的许可证。
- **成品任务单轮成稿底线（反缩水红线）**：用户首轮点名要成品（报告/计划/综述/对比表/申报书/提纲等交付物形态）时，本轮必须交付**完整成品**——候选卡、阶段推进、收敛提问只适用于用户未点名成品的开放咨询；多轮流程纪律（分阶段、先收敛、下一轮承诺）绝不构成首轮减少交付量或降低成稿度的理由。成稿度以用户口径衡量：要 N 项就给满 N 项、要字数就贴字数、可自助检索补齐的条目先补齐再交付——「精而薄」不是「全而厚」的合格替代。直答纪律与本条同向：反问前先交直答部分，直答就交到成品粒度。
数量配额的达成**不得以降质凑数为手段**：约束内凑不满就报缺口，绝不用不符合约束的条目、裸条目、降档条目填数——「达标」指满足用户全部口径的达标。
