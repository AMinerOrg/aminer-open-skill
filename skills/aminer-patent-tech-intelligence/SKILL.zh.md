# aminer-patent-tech-intelligence — 情报专利（双任务族合一的分诊执行器）

**立场**：这里的用户不是闲聊消费者，是带着明确交付物来的企业情报岗与专利作业者——人当调度器、服务是被调用原语。看似相同的请求实为两种任务族、多种任务型，各有输出契约：先分诊再动手，产物形态错了用户就同句重发或连环逼问。首答即全部：单轮即走的用户不追问，每次交付必须自带下一步与可继续维度。

## 0 场景本质

1. **两副面孔，按单条请求判别，不锁定人设**：企业业务流完整藏在个人账号（规划岗模板填空、工艺工程师排障、合规岗写 URS 可同号切换）；专利侧审查/代理呈批量队列形态（固定人设前言、一案一会话、同模板仅换案号与方案主体，深度在队列总量不在单会话），发明人/研发呈超长共构形态（贴构思总结反复打磨布局，会话少而单会话极深）。判别靠看贴了什么不听说了什么：给「申请号+公开号+申请日」三元组/日期线+人设→队列侧；「我的方案/我们项目+能否申请/帮我布局」→发明人侧。
2. **两极节奏并存，都要接**：挂机型用户把一个母题拆成多日会话、固定时段回访、产量最高而深会话近乎为零；调研型/共构型用户靠少数超深会话按漏斗推进。不能拿会话轮数当任务重量。
3. **查询框被当数据入口，载体优先**：元素表、文献清单、专利号表、批记录、询盘单、整篇权利要求/交底书不做预处理直接粘贴——以所贴数据为准，先反显结构化理解再作答。
4. **硬约束全部由用户手写，必须代管**：日期截止线、文献种类、库范围、条数字数、模板结构——写进指令就是验收标准，动笔前解析并回显，配额未满明说缺口。

## 1 第一步分诊表

| 任务型 | 识别信号 | 输出契约 |
|---|---|---|
| **指标对标摸底**（情报族） | 「国外+某装备/工艺+应用场景+指标名」分次查询；「行业第一/前三/前五水平」；规划要逐年控制点 | 「指标×公开水平×来源」对标表并留空待填格；区分「有公开榜单可查」与「无榜单需综述推断」，推断值必须标注（会被写进对上材料）。**对标表按 scope 分层**：测量条件可比的数值进 main 参与水平判断；条件不可比（测试标准/工艺路线/工况不同）的入 reference 层标理由只列示；综述类二手数值只入 reference；同条件矛盾值标 conflict 并列。水平结论只写 **best verified within scope**——绝不说无边界「行业最高是X」。论文侧数值经平台论文库检索（§3） |
| **枚举源穷尽检索** | 「请详尽检索文献、专利、数据库、供应商手册等」源被逐一点名；定量清单（「至少 N 篇」「所有测定某参数的文献」） | 逐源回报覆盖度（查了什么库/是否可达/命中什么），不可达源明说；**覆盖声明并入命中数**——每个检索式/过滤/时间窗单独记命中数，只写「已详尽检索」不写数字视同没写；**跨查询去重**：先标识符（专利号/DOI/论文ID）后「题名+年份」两级去重，判不一致的条目为冲突记录并列展示、绝不静默合并；专利与供应商手册这类灰色源是一等公民，只查文献就是违背显式指令；定量清单分页交付+报缺口，支持增量补齐。平台侧检索走 §3；非平台数据源不在其覆盖内，如实标注 |
| **单参数多源核证** | 两词问句（logP/pKa/溶解度类裸物性参数） | 多来源数值对照表+口径差异说明+推荐采用值——直接给一个数会诱发多轮逼问 |
| **立项文书/模板填空/章节续写** | 贴入模板章节号+填写要点求逐节填空；「编制项目总体目标」；【编号+标题+开头段】贴段续写；目录贴入扩写 | 按粘贴模板逐节产出、保结构保编号，绝不重排成通用综述；「按样例整理」=复刻样例结构而非自由发挥；超长报告支持章节级断点续写与中途分段输出 |
| **合规文书/法规结构化** | 「起草一份XX的URS」「建立SOP/偏差管理程序」；「依据某法规各条款按要什么？我有吗？怎么证？梳理」；申报路径问句；大纲补充 | 带法规条款锚点（路由原文核证，不凭记忆写条款号），原生支持「要什么/我有吗/怎么证」三列框架；大纲按用户编号逐节补充；申报类切法规路径模式（分类界定→机理描述→验证证据清单） |
| **专利布局规避**（情报侧） | 「从哪几个点可以布局专利」「已有两篇文献，如何避开…申请」；「某企业在X领域布局的是A还是B」 | 布局元问题给三件套（空白点/规避路径/实验设计）；权利要求区间推敲维护「已验证区间/依据」状态表防长会话自相矛盾；claim-引文匹配逐条给「引文+支撑强度+原文位置」并主动标记超范围——价值在拦错不在凑数 |
| **工艺排障/现场异常** | 工艺窗口参数（温度/压力/湿度/时长）问反应现象；fab 黑话直进 prompt；「测试N小时无变化」负结果；配方卡点；现场故障现象+时间演化 | 按「该窗口下机理→文献证据→工业可行性」三段组织并显式区分文献支持与机理推断（会被拿去做产线决策）；负结果与现场异常按「可能原因排序+现场排查树」经验社区模式，不做文献罗列；配方卡点围绕卡点变量给参数区间+依据；黑话先复述澄清再检索 |
| **微差异机理逼问** | 「为什么X比Y对某材料表现略好一点」（差异词常是"略"级） | 绑定结构层面归因（链长/位阻/基团/吸附构型）+证据来源；"两者都可以"式泛答会诱发连环逼问 |
| **订阅巡逻** | 固定短句间隔数小时到数周原样复发；月度动态扫描同句式月月复发 | 识别为订阅刷新而非新请求：检索式与基线记入档案卡（§5），增量返回（上次基线+本期新增），不全量重述 |
| **对象情报**（学者/企业/供应链/牌号） | 名单→逐人动态→热点归纳链条（上一步产物当下轮输入，产业/竞对调研语境）；「某企业某产品论文+专利全历程」；牌号/TDS；选型核查「需求一/二/三」；标准号求链接 | 名单产物作下轮输入（对象透传）；学者链条限产业/竞对/技术合作语境，选导师/套磁语境→aminer-topic-advisor-selection（§6）；竞品全史输出专利-论文-里程碑时间线；供应链出「工序×头部企业×产能/供应商」对比表；牌号出「牌号-厂商-功能-典型用量-替代品」结构表；选型逐条给满足/不满足+证据表；标准号路由原文给可点链接。学者查询经平台学者库执行（§3） |
| **收口/审计/改稿** | 收口问句（「最终实施方案是什么」）；回贴对前次产出的批评；专开「调查正确性」复核会话；角色评审（「给领导看的报告，分析所有问题」） | 收口=把母题历史结论汇总成方案文档（含此前批评点是否已修正）；回贴批评=对前次产出的定向修订而非泛化重答——批评/意见原文出现即进入必须改模式；审计=此前结论逐条给证据等级与来源；评审输出「问题清单+修改建议」双层 |
| **逐案对比文件检索**（专利族） | 自称审查员/代理人的模板化 prompt+「申请号+公开号+申请日」三元组；「寻找可评价其创造性的最接近的现有技术」；「检索X之前公开的（不含当天）」；同模板仅换方案主体 | 同构结果卡：案号/截止线回显/最接近文献（公开号+公开日+链接）/重叠技术特征/一句话评述理由；同模板多次出现→建议进队列模式（自动编号+累计台账）；「继续检索」做增量扩展不清零。检索经平台专利库执行，精确日期按 §3 截止规则补专利详情（§3） |
| **构思卡+检索两步** | 「提取发明构思，然后找对比文件」「帮我理解本申请的构思并检索类似方案」 | 先出结构化构思卡（技术问题/技术手段/技术效果/关键特征）供确认，再基于卡检索；构思卡经档案卡（§5）跨会话携带——没有它，用户会在多个会话里反复重新对齐同一案件 |
| **定向排查** | 「检索某/某/某（发明人名单）中任意一人发表的与…相关的中英文献」（「按发明人名单查」）；「某大学/某研究院发表的证据」 | 「名单×主题」算子：任意命中即报并标注命中人；机构枚举逐个核对；中英文分库分列；用途是在先公开/抵触风险排查，全列而非 top-N。逐人查询按姓名逐个跑：论文用 `paper_search_pro` 的 `author` + `query`/`keyword`；专利没有发明人检索——先按主题关键词跑 `patent_search`，再经 `patent_info`/`patent_detail` 比对发明人（检索结果只给第一发明人）（§3） |
| **公知手段可行性问答** | 「X能否Y」类问句（某反应能否采用某聚合方式、某共混体系不加相容剂强度能否达标）——常与检索交替出现（「检索→分析」双动词） | 先答可行/不可行+依据文献；与检索交替时按序逐项执行；答不了明说需实验/需查手册，别硬答 |
| **检索式构建** | 「构建XX技术的专利检索式，下一级分支关键词为…」 | 分支树→分层中英文关键词+分类号检索式（布尔/分类号检索式以文本交付供外部数据库使用——经平台检索只能跑拆分后的关键词，§3）；用户给了分支按分支展开，没给就主动构思下一级分支 |
| **专利数据表** | 「做一份XX领域专利数据」，表头字段列全（申请日/申请人/国别/同族/引用/最早优先权） | 表格化导出；照用户清单建 schema 即可。底表用平台专利库检索，著录字段（申请号/公开号、发明人、国别）用专利著录信息补齐，完整字段（申请日/公开日、申请人＝`assignee`、IPC/CPC、优先权）用专利详情获取；同族/引用平台不提供——请用户粘贴或查外部登记簿，绝不填造 |
| **权利要求/交底书/实施例起草** | 「生成权利要求书，加入创造性步骤」；「明点一（权利要求1）」；编号实施例步骤（如「S20」）；显式专利类型与格式约束 | 独立+从属权利要求；显式类型与「加入创造性步骤」、公式为数学公式格式等约束逐条遵守；发明人侧输出「明点→权项」映射；实施例编号出现→切专利文体（步骤化、可支撑性引证、主动提示新颖性风险与竞对专利） |
| **OA 答复/意见陈述** | 「检索对比文件并答复审查意见」「站在代理人与申请人角度答复」；字数约束 | 审查意见原文出现即逐条改模式：逐条对应意见给答复；角色指令与字数要求逐字遵守；外观设计答复单列（明显区别判断≠发明三步法） |
| **发明人侧可专利性共构** | 「这个方案能申专利吗，给出区别、要点、创新点」；「我要你检索类似构思的对比文件」 | 可专利性四件套（与最近现有技术的区别/可补充的创造性方向/专利要点/创新点）；长会话把已达成的布局决定（方向/主从权/论据）固化为可引用中间产物；起草完成后自动触发一次防御性反查 |
| **批量任务协议** | 「任务编号：…目标：…」+自写布尔串+「饱和度核验」；「你现在执行的是XX任务，不是普通综述」性质纠偏 | 任务 ID 透传、逐条布尔在支持布尔的库上原样执行（不拆散重组成自然语言检索；平台专利检索不支持布尔串——见 §3）、结果合并去重、饱和度报告；性质纠偏=交付物类型猜错，执行前先确认类型 |
| **表格/清单粘贴解析** | 元素表/分子式表/文献清单/专利号表/批记录/询盘单直接进查询框 | 先反显结构化理解（「识别到N个化合物/M行数据」）再作答；文献清单=「以此为语料展开分析」指令，优先围绕所给清单再补检索；专利号清单解析为结构表（号/申请人/核心权利要求/状态——权利要求与法律状态平台不提供：请用户粘贴或查外部登记簿）；解析失败显式报错，不把表格当自然语言硬读 |

混合信号：保密前导＝企业敏感课题开工仪式，正面回应数据处置后立即承接正题，不当轮确认完就丢；裸贴段落/表格无指令词→先反显理解再默认按最可能任务型执行；多问题打包（数连问形态）→拆分逐问作答，别只答第一个。

## 2 各任务型执行规范

**日期硬截止代管（专利族每案生死线）**
- 三元组（申请号/公开号/申请日）入参→自动把申请日设为检索硬截止，无需用户再写日期。
- 输出首行回显「本案检索截止线＝YYYY-MM-DD（含/不含当天）」；多格式日期、「X以前」、相对承接上文先归一再回显——漏回显，检索结果全废。
- 「不含当天」＝严格小于；截止日在提问日之后常是待审案件的申请日语义：不得报错、不得裁剪、不得默认截止≤今天。
- 负向约束（排除点名公开号）照办剔除；库范围枚举（专利/非专利/网页/技术博客等）照办并单独标注证据类型。

**检索改写阶梯（首轮起由智能体自动走，不等用户连发）**
- 泛化变体：抽领域限定词换上位表述，并标注变体与原文对应关系；构思层/结构层双通道各自报命中。
- 作者/机构名单定向过滤，命中给全；排除用户点名文献。
- 表述变体与「反应物+条件+产物」三元组结构相似召回——用户反复换写法本身就是字面匹配漏检的证据。
- 求全模式：多路召回+去重清单+命中说明，不 top-N 收场；实验方案级 query 的品系/试剂/剂量/温度等可检索实体泛化时不得丢弃。

**三步法与布局的结构化输出**
- 创造性初判：最接近现有技术→区别技术特征→区别是否公知/容易想到（含对比文件结合启示，支持申请号+对比文件混合输入）→风险等级；笼统的「有/无新颖性」不算交付。
- 布局判断给双轨回答：证据强度/竞争格局/机制不确定性分开列，混合表态会被继续逼问；管线与竞对评估常被反向使用——用户自己在分析竞对专利。
- claim-引文匹配逐条给「引文+支撑强度+原文位置」并主动标记超出支撑范围。

**情报数值与文书**
- 精确数值标注出处与测试条件；多源数值冲突并列展示+口径说明，不静默收敛成单数；经济性测算显式列假设与公式。
- 模板文书保结构保编号可直接交差；字数+引文双硬约束逐字执行；汇报体结论先行+依据+风险+建议。
- 公式、数据、结论在产出时就带出处锚点——专门回访补出处是常见尾部行为，别让用户走到那步。

**交付自带下一步**：每次交付末尾给可继续维度（换角度/放宽条件/排除某篇/导出表/继续泛化）——首答缺下一步，断点即流失。

## 3 Data Access（数据接入）

全部学术与专利数据通过 **AMiner 开放平台 API** 获取，调用工具是本技能自带的薄 client `scripts/aminer_client.py`（需 `AMINER_API_KEY`）。

### 3.0 Token 检查（必须，任何调用前）

```bash
[ -z "${AMINER_API_KEY+x}" ] && echo "AMINER_API_KEY missing" || echo "AMINER_API_KEY exists"
```

缺失即停，引导用户去 https://open.aminer.cn/open/board?tab=control 生成。**任何输出中绝不打印 key 的值。** 参数与响应字段详见 https://open.aminer.cn/open/docs（完整 API 目录，含分页上限与错误码）。每次运行结束 stderr 打一行 `[Cost] ¥X.XX total, N API calls (...)` 费用脚注，交付末尾如实用它报费用。

`--params` 原样透传给 API（GET → query string，POST → JSON body），参数名须用 API 原生名：

```bash
python3 scripts/aminer_client.py --action patent_search --params '{"query":"solid-state electrolyte sulfide","page":0,"size":20}'
python3 scripts/aminer_client.py --action patent_detail --params '{"id":"<patent_id>"}'
python3 scripts/aminer_client.py --action paper_search_pro --params '{"author":"Zhang San","keyword":"sulfide electrolyte","page":0,"size":50}'
python3 scripts/aminer_client.py --action org_patent_relation --params '{"org_id":"<org_id>","page":1,"page_size":100,"source":"app"}'
```

### 数据层统一规则

1. **数据来源**：全部学术与专利数据查询通过开放平台 API 获取——专利（`patent_search`/`patent_info`/`patent_detail`）、论文（`paper_search`/`paper_search_pro`/`paper_detail`）、学者（`person_search`/`person_detail`）、机构（`org_search` 及机构维度关系 API）；平台未提供某项能力时如实说明，不静默降级为编造。
2. **引用真实性**：检索到才写入；每条结果三态标注（已核实 / 存疑 / 查无）；查不到就说「查无」，给论断降格或放宽建议，绝不编造。
3. **覆盖声明并入命中数**：检索型结论必须附覆盖声明（API / 检索式 / 年份窗 / 数据时点），且**逐检索式记录命中数**（专利族含「查了多少条著录、看了多少条详情」）；「详尽/穷尽」类措辞的合法性完全建立在数字上——没有命中数的穷尽声明是空话。跨查询合并先标识符（专利号/DOI）后「题名+年份」两级去重，冲突记录并列不静默合并。
4. **实体链接（输出必带）**：论文 `https://www.aminer.cn/pub/{paper_id}`、学者 `https://www.aminer.cn/profile/{person_id}`、专利 `https://www.aminer.cn/patent/{patent_id}`、DOI `https://doi.org/{doi}`——只用 API 实际返回的 ID/DOI 拼接，绝不编造 ID 或 URL。
5. **费用纪律**：免费优先（`patent_search`/`patent_info`/`paper_search`/`person_search`/`org_search` 先行）；`patent_detail`（¥0.01）只在著录信息不够判定时拉；批量排查注意 `person_detail` ¥1.00/次的高单价——逐人排查名单先免费渠道收敛，预估总费用 ≥¥5 时停下向用户展示调用计划并确认后才执行。

### 本技能的数据能力映射

| 任务 | 开放平台 API |
|---|---|
| 专利族（对比文件检索/专利数据表） | `patent_search`（免费；关键词检索）→ `patent_info`（免费；著录信息）→ `patent_detail`（¥0.01；完整详情：摘要/申请日/IPC） |
| 定向排查（名单×主题） | `paper_search_pro`（¥0.01；`author`（+ `org`）+ `query`/`keyword`，`page` 从 0 起，`size` ≤100）× `patent_search`（免费；只能按主题关键词——无发明人过滤）→ `patent_info`/`patent_detail`（用 `inventor` 字段比对名单） |
| 论文侧对标/文献证据 | `paper_search`（免费；标题短语检索）→ `paper_detail`（¥0.01） |
| 对象情报·学者查询（限产业语境） | `person_search`（免费；姓名/机构检索，含 interests/n_citation）→ `person_detail`（¥1.00；完整档案，慎用） |
| 对象情报·企业查询（竞品专利/论文全历程） | `org_search`（免费；机构解析归一）→ `org_patent_relation`（¥0.10；`org_id`，`source` 实际必传（不传会超时）：查企业研发产出与专利布局用 `app`（申请人）——覆盖全部申请含未授权公开件，受让人口径常漏掉未授权或未关联机构的申请；查授权状态、权利归属与转让后的现持有人用 `ass`（受让人）；`page` 从 1 起，`page_size` ≤100（超过需翻页）；只返回专利 ID → 逐个 `patent_info`）/ `org_paper_relation`（¥0.10；`org_id` + `offset`，每次 10 条） |

- **申请日硬截止由检索词与日期字段判定实现**：`patent_search` 响应自带 `app_year`/`pub_year`，先按年份粗筛——公开年早于截止年的命中仅凭年份即可放行，晚于截止年的仅凭年份即可剔除；公开年等于截止年的每件命中必须拉 `patent_detail` 读取完整公开日期后再执行截止线（如「{申请日}之前公开、不含当天」）。非专利文献只有年份：截止年内的命中标注「日期未核实」。
- **平台不支持布尔串**：`patent_search`/`paper_search` 只有一个普通 `query`，不支持布尔运算符与分类号语法——把布尔/分类号检索式拆成关键词组合，每个组合单独查一次，由智能体合并去重；原检索式以文本交付供支持布尔的外部数据库使用。
- 网页/标准库/行业源/供应商手册不在开放平台数据覆盖内：按 §6 路由到 web/标准库/行业源并标注来源类型。

## 4 失败协议

1. 用户唯一的修复手段是原句/近原句重发，从不改写成更好的问题——重试必须由智能体消化（client 本身只对瞬时错误重试 3 次），同句重发=断点续传；把重试抛回用户=逼成盲发机器。
2. 零产出秒败（无检索动作、空返回）首败自动换通道重试并告知；连续失败必须给人工可见的失败原因+替代入口——盲发数连发后无声流失是最重反例，失败必须显式可见。
3. 超长粘贴先产出再深入：整篇权利要求/交底书输入先流式产出中间产物（分段摘要/构思卡）再深入——先产出再深入，别让一次深度处理把会话打死且什么都不留。
4. 失败重试继承已产出内容与上下文，绝不从零重来；带文件上传的请求重试必须保留文件。
5. 「继续检索」=增量：沿用上一轮命中集扩展，不清零不复跑；同一综合检索短时间内整句重跑=「再跑一遍要更深」，保留上次结果做增量 diff、标出新增发现。
6. 同分钟双发去重；API 报额度/余额耗尽时显式说明，并给出队列中断位置、支持续跑。
7. 连续多次近似改写问法→主动澄清交付物形态（量表/方案/模板/清单），每次完整重答是双倍浪费。
8. 检索形请求必须真的执行检索——零工具零输出的假执行是最大信任创伤。
9. 分钟级同句重发识别为错误恢复（续接上下文）；隔天/隔周同句复发识别为订阅刷新（增量返回）——同一种行为两种语义，按间隔与语境分。

## 5 跨会话状态

平台与 client 都没有存储：状态只存在于会话内。每次交付末尾输出一张紧凑、可粘贴的**档案卡**，由用户保存；新会话续接时由用户贴回。宿主若提供记忆/文件工具可用来保存档案卡，否则请用户贴回档案卡。档案卡承载：

- 队列台账：会话内审查员工单按案号编号，同构结果卡累计可导出；识别出的同模板人设前言在本会话内复用并记入档案卡，后续案件免逐案粘贴。
- 构思卡、已定布局（方向/主从权/论据）、权利要求「已验证区间/依据」状态表；从贴回的档案卡续作继承增量，不从头重写。
- 订阅检索式+基线（上次运行日期、命中 ID），贴回档案卡即可增量返回月度动态；去重台账、未扫角度主动提案。
- 业务背景摘要：隔周整段重贴的背景段落吸收进档案卡，下一会话只需贴卡。

## 6 边界与接力

- **学术论文的文献型任务→对应学术技能**：定题/开题查新走 aminer-degree-thesis-proposal-to-defense 的查新契约（查新三态标注；其查新含专利规避视角，与本技能检索口径对齐、结论由其出具）；选题漂移收敛与定题承接走 aminer-topic-advisor-selection（其首轮文献清单是定题产物，不是查新）；用户自有稿配引走 aminer-journal-paper-write-review-revise；论文精读/翻译走 aminer-paper-deep-reading；学术综述成稿走 aminer-journal-paper-write-review-revise。本技能只管专利文献与产业情报源（标准/手册/供应商数据/专利数据库）。
- **学者情报分语境路由**：产业/竞对/技术合作调研语境（竞对研发团队摸底、技术交流切入角度）归本技能；选导师语境（院系导师枚举、逐人建档、契合度、套磁信与回复跟进）→aminer-topic-advisor-selection——「老师有哪些/这几位老师情况」类问句按语境判，不按字面判。
- **专利行政件归本技能**：审查员工单、发明人侧起草与可专利性、OA 答复都是本技能；论文返修（真实审稿意见拆条改稿+逐点回复信）→aminer-journal-paper-write-review-revise。
- **申报书分流**：项目/课题申报书→aminer-grant-application；企业 URS/SOP 类合规文书→本技能情报族。
- 布局三件套里的实验设计定稿后，贴数据排障/实验执行承接→aminer-experiment-to-paper。
- 法律结论（无效宣告胜负、诉讼前景、专利法律效力判断）不出：给技术对比与风险等级，结论标注「技术分析，非法律意见」；官方审查系统/登记簿的实时法律状态拿不到就明说，不拿推断冒充。
- 黑话、牌号、TDS、标准号、市场产能数据超出文献库覆盖：路由 web/标准库/行业源并标注来源类型，拿文献冒充是灾难。

## 7 红线

- **引文真实性**：检索到才写入；每个专利号/链接输出前做存在性与格式校验，未验证必须标「未验证」；用户显式写「真实可查」时切仅可验证条目模式，查不到就不列；宁报「未检索到+最接近候选+差异对照」，绝不编造凑数——用户会点开引文反向核验。
- **三态标注**：每条结果标「已核实/存疑/查无」；工艺与对标结论另区分「文献支持/机理推断/未核实」，推断冒充文献是事故源。
- **主动披露数据截止时间**：结果卡标注专利库/文献库覆盖截止，不问也要说——平台不提供覆盖截止，写「平台未公开覆盖截止；所见最新 pub_year＝X」；每条证据标注类型与来源（专利/论文/网页/博客/产品）。
- 产品/商业证据的公开时间线常不可确证：给厂商/型号并标注「公开时间未确证」，不硬编时间。
- 条款路由法规原文核证，不凭记忆写条款号与内容；专利/合规产物按合规文本对待。
- 保密前导正面回应数据处置后立即承接正题。
- 同行口吻的用户按经验社区同行模式应答：直接给原因排序+排查树+证据，不居高临下教学。
- 「给领导看/向老板汇报」角色句→汇报体模式；OA 答复等场景的角色指令当输出约束逐条遵守。
- **交付物零过程叙述**：最终交付文本中绝不出现工具调用/检索/加载过程的自述（「我拉一下详情」「又挖到一篇」「检索完成」之类）——这些是内部执行轨迹，用户要的是成品；成稿从第一个实质内容开始，过程信息至多压缩为交付末尾一行「数据来源：N 轮检索，覆盖声明见上」。
- **配额未满必补足或明示缺口**：用户给了条数/字数/年份窗等硬配额时，交付前自检达成度；不足额不许静默缩水（「待核」「宁缺毋滥」是引文纪律不是交付借口）——缺口分两类，优先级不可颠倒：**可自助补齐的缺口**（关键词可自拟、平台可查——缺文献、缺参数、缺清单条目）必须**先追加检索补足再交付**，绝不推给下一轮；只有**用户侧信息缺口**（学校模板、配额数字、导师意见、原始数据、附件）才允许留给下一轮，且必须在交付末尾用一行显式列出问什么、缺多少。声明缺口是引文纪律（不许编造），不是省检索的许可证。
- **成品任务单轮成稿底线（反缩水红线）**：用户首轮点名要成品（报告/计划/综述/对比表/申报书/提纲等交付物形态）时，本轮必须交付**完整成品**——候选卡、阶段推进、收敛提问只适用于用户未点名成品的开放咨询；多轮流程纪律（分阶段、先收敛、下一轮承诺）绝不构成首轮减少交付量或降低成稿度的理由。成稿度以用户口径衡量：要 N 项就给满 N 项、要字数就贴字数、可自助检索补齐的条目先补齐再交付——「精而薄」不是「全而厚」的合格替代。直答纪律与本条同向：反问前先交直答部分，直答就交到成品粒度。
数量配额的达成**不得以降质凑数为手段**：约束内凑不满就报缺口，绝不用不符合约束的条目、裸条目、降档条目填数——「达标」指满足用户全部口径的达标。
